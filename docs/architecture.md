# Architecture and consequential choices

The project uses Svelte 5 runes, TypeScript 6, Vite 8, Tailwind 4, and DaisyUI 5. Exact compatible installed versions are in the npm lockfile; Svelte's checker and production build validate their integration. Vite's static build is sufficient: there is no server routing or application backend in the web mode, so SvelteKit would add a layer without a current need. Theme tokens use the Catppuccin palette; system fonts avoid network font dependencies.

Tauri 2 shares this frontend with the Linux app and embeds the OS's maintained WebKitGTK engine. The Rust layer provides filesystem reading, native selection, explicitly supported external URL schemes, sandboxed Typst compilation, and sandboxed LaTeX compilation using a user-selected executable. Diagram export writes only to a location chosen in a native save dialog; there are no source-editing commands. Blocking work runs on Tauri's thread pool. Nix packages GTK, WebKitGTK, libsoup, Typst, Bubblewrap, and their runtime closure; LaTeX uses the user's installation. Other desktop platforms could implement the same `Source` interface but are not declared supported.

While the Linux app runs, a per-user Unix socket exposes the control API used by `papyri ctl` and editor integrations. The socket is separate from document-frame IPC: each request is forwarded to the top-level host and answered through a bounded request map, while the host's calls back into Rust use the same host-token-authenticated IPC as other application commands. Native-only methods (`ping`, `raise`, and `quit`) are handled without the webview. The host publishes throttled `state` and `headings` events only after clients subscribe. Socket permissions restrict access to the same user. Requests carry a deadline, queued mutations that expire are skipped, and a request waiting on work already underway still times out rather than queueing indefinitely. See [control API](control.md) for the protocol and CLI.

PDF, Typst, and LaTeX tabs retain binary PDF data separately from Markdown text. Native PDF reads and compiled output use Tauri's binary IPC response instead of large JSON number arrays. PDF.js owns page rendering, text selection, search, links, and outlines in an opaque-origin frame. Its classic bundled worker can run from a Blob inside the sandbox; module workers cannot reliably load there. CMaps, standard fonts, and WASM image decoders are bundled separately and loaded on demand through a manifest-restricted host bridge, with no cross-origin fetch or CDN. Page rendering uses PDF.js's rendering queue and cache. The PDF bundle loads only for paged documents; ordinary Markdown retains its existing path. Typst uses a selected or discovered CLI with the Nix-pinned CLI as a fallback; LaTeX uses an installed engine. Both return a PDF to the shared renderer. See [document support](documents.md) for compilation scope, fonts, packages, resource limits, and browser-mode differences.

`Workspace` owns source identity, normalized document paths, tabs, file content, revisions, errors, scroll positions, and one-time heading commands. Source auto-selection is guarded by the same navigation generation as document reads, so a delayed listing cannot override a newer source or user navigation. Heading commands are consumed after being sent to a ready frame and are cleared on tab/source changes; they cannot replay during refresh. `Source` adapters distinguish a Linux filesystem, a browser folder grant, and a selected-file snapshot. Directory UI expands one level on demand and pages DOM rows in groups of 200; filesystem listing itself returns the immediate directory, not a recursive workspace scan. Browser handles and imports have virtual-root paths and cannot escape their selected root. Both browser adapters reject oversized files from their metadata before allocating a buffer and validate the byte limit and UTF-8 again after reading. A changed source invalidates pending navigation and old tabs. Polling is serialized, checks only visible documents and expanded directories, pauses in the background, and retains a stale preview when a file disappears.

The command palette (Ctrl K or Cmd K) searches file names and paths beneath the explorer's current directory and offers app actions. It uses filter tabs for all results, files, commands, headings, open tabs, source text, recent folders, and PDF pages; the Folder / Parent / Workspace scope control is a segmented toggle rather than a dropdown. A prefixed query selects the same modes directly. It scans on demand, skips symbolic links, and stops after 2,000 directories or 20,000 entries. It reports incomplete results and inaccessible folders, and shows at most the 100 best matches. Closing the palette or changing sources cancels the scan, and each subsequent opening scans again so directory changes are reflected.

Palette actions cover opening and importing, search, tab and split navigation, directory navigation, document and interface zoom, fit to width, themes, external resources, refresh, settings, and help. The Linux app also offers LaTeX engine selection. Actions requiring a document, multiple tabs, an open search or split view, or a parent directory appear when applicable. Search also matches common alternate names such as “sidebar” and “preferences”.

The palette remembers recently opened files and commands for the current session. Prefixes select commands (`>`), headings (`@`), open tabs (`%`), source text (`?`), recent folders (`~`), or a PDF page (`#`). The same modes are available from the filter tabs, which show each prefix as a small keycap. The segmented scope control searches the current folder, its parent, or the selected workspace folder. When a query word is close to a command, heading, recent place, or file name, the results list offers a single “Did you mean …?” spelling correction; selecting it replaces the query and keeps the palette open. Text search matches a literal phrase case-insensitively in Markdown, Typst, and LaTeX source; it does not search PDF files. It displays the first matching line per file and opens the document with the phrase in document search. Source markup or compiled output may not contain that exact phrase. Text search is limited to 500 files, 500,000 characters per file, 4 million characters total, and 100 results; skipped content is reported as incomplete. No source files are compiled for this search.

Markdown parsing and highlighting run in a disposable module worker, with an 8 MiB byte limit, 15-second timeout, and cancellation on navigation or rendering-setting changes. A bounded 32 MiB / eight-entry LRU reuses parsed markup across tab switches, without retaining assets, file permissions or trust. Presentation changes use a separate message channel: theme, fit-to-width and independent document/UI magnification update existing DOM without reparsing, reloading fonts or discarding diagrams. Markdown-it plugins supply syntax; GitHub Slugger supplies unique GitHub-style heading IDs through a renderer hook. The initial anchor-plugin candidate took quadratic time on repeated headings; a measured switch to the slugger hook avoids that behavior without replacing the Markdown parser.

The parent prepares only bounded, statically referenced image assets. Every preview is an opaque-origin `srcdoc` frame with a dedicated CSP, DOMPurify sanitization in safe mode, no `allow-same-origin`, and no file-read message protocol. Generated equation and bibliography targets are marked during parsing and assigned collision-free IDs against the sanitized document DOM, preserving authored IDs and GitHub-style heading slugs. The parent loads the bundled renderer once; each isolated frame owns its rendering state. Native trusted script elements receive Tauri’s response nonce without disabling its automatic CSP protections. The frame runtime and diagram runtime are separate IIFEs because module imports from an opaque `srcdoc` origin need server CORS headers that GitHub Pages and Tauri need not supply. Fonts and Graphviz WASM are embedded, making this artifact larger but self-contained. On the first Render action, the frame requests the fixed diagram bundle from the parent and executes it with the frame nonce; the parent accepts requests only from the current frame and channel. Previews do not fetch it before that action. There is no diagram layout cache or document DOM virtualization yet.

The iframe counteracts inherited application CSS zoom at its embedding boundary, so UI magnification never changes the document coordinate scale. Document font size and reading width therefore need no inverse UI scaling. Each frame owns its viewport sizing. A small runtime reads the frame's layout viewport on startup, presentation updates and window/visual-viewport resize events, then supplies CSS pixel dimensions to the document and diagram dialog. This follows window resizing, explorer and outline changes, split panes and UI zoom without measuring document content or feeding its scroll width back into layout. WebKitGTK scales root `clientWidth` and CSS viewport units by ancestor CSS zoom while reporting the unscaled viewport through `innerWidth`; using the root as a width oracle can therefore accept a document that spills beyond its pane. Tests compare content bounds against the frame viewport and the host's physical iframe bounds instead. Visual viewport dimensions exclude scrollbar space at normal visual zoom; pinch zoom retains the layout viewport.

Search and anchor commands go into the frame. Only validated navigation and bounded scroll messages come out in safe mode. Current frames can also acknowledge readiness, request bounded document/UI zoom and width changes, expand/collapse a diagram, and cycle existing open tabs. These messages accept no file paths or arbitrary filesystem operations. Document zoom adjusts root font size and reflows text; UI zoom is isolated at the frame boundary. A frame starts with a themed background and stays hidden until its styled DOM is ready. Diagram expansion moves the live output into a native HTML dialog while the host gives its existing frame the window area, preserving SVG IDs, chart state and sandbox boundaries. Script-enabled frames have their host navigation channel disabled. Each split pane resolves links against its own source document. Native commands additionally require a cryptographic session token injected into the top-level host only, because Tauri's Linux IPC capability model alone cannot distinguish child frames reliably. Built-in plugin IPC receives no permissions; native picker and opener APIs are reached through authenticated application commands.

Settings, help and trust prompts share the `openDialog` action. It measures the visible viewport before opening and updates the dialog's viewport dimensions and offsets on window/visual-viewport resize and pan events, removing listeners on destruction. The top-layer overlay counteracts inherited UI zoom; its panel reapplies UI zoom while dividing its measured width/height budget by that scale. This keeps the panel's physical bounds at 75% width and at most 80% height, preserving larger text without relying on WebKit's zoomed CSS viewport units. The grid has no content-based minimum track size. Container queries stack delimiter fields and shortcut descriptions; flexible rows and buttons wrap, and the panel owns vertical scrolling. Expanded diagrams use a centered content-sized panel bounded by 90% of the frame, with local zoom and scrolling for the artwork.
