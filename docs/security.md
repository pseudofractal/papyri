# Security model

Diagram export requests use the authenticated current-frame message channel. Script-enabled previews cannot request exports. The host validates the requested format and size, and native downloads require a save dialog.

Safe preview is the default. Markdown and raw HTML never enter the privileged application's DOM. DOMPurify sanitizes the rendered HTML inside an opaque-origin frame. The frame has `sandbox="allow-scripts"` solely so bundled renderers can run; it has no same-origin, forms, popups, downloads, or top-navigation grants. A CSP restricts sources, blocks object embedding and form submission, disables network resources by default, and permits bundled Graphviz WASM without JavaScript `eval`. When network resources are enabled, hovering an external link may load its destination in a nested frame with all sandbox permissions disabled, or as an image; the remote site receives a request, but no referrer. Some sites block embedding. The host CSP permits HTTP(S) frames so those previews can work in Tauri; the document frame's own CSP controls whether they can load. The host's CSP allows the bundled frame runtime and WASM. Tauri's automatic CSP modifications remain enabled. An inert meta tag uses the locked Tauri SDK's nonce placeholder, which Tauri replaces and authorizes per response. The host gives that nonce to the bundled frame runtime, which assigns it to document script elements only after explicit trust. No host-wide script/style policy relaxation is used; it is not the primary defense against document injection. The host never inserts document HTML into its live DOM.

The diagram runtime is supplied by the parent only on request from the current preview frame, and cannot be substituted through document IDs. The parent scans static image references in an inert template, resolves them against the current document, checks type and byte budgets, and embeds bytes into the frame. Direct `data:image/*` sources are rendered without a host read. Referenced local images grant a document access to those files under the account's Linux permissions. Do not treat a document with arbitrary image paths as having no read access at all. User-selected web imports are confined to their selected file set; directory handles are confined to their grant. There is no message allowing a frame to request arbitrary bytes, and no global asset protocol granting a webview broad filesystem access.

PDF previews can request bundled PDF.js fonts, CMaps, and decoders through their current-frame message channel. The host accepts only filenames in its generated resource manifest, restricts their syntax and size, and fetches them from the bundled resource directory. The protocol cannot read arbitrary local paths or URLs.

The socket is not a network service. The control API, `papyri ctl`, and the
integration examples are documented in [control API](control.md). Because any
process running as the same user can connect, the socket is a convenience
boundary rather than a privilege boundary; it exposes no operation the GUI user
could not already perform.

Tauri warns that Linux cannot reliably distinguish iframe IPC from host requests. Therefore every application command additionally checks a random 256-bit per-process host token. Initialization exposes the token only when the frame is the top-level application at the expected application/dev origin. An opaque document cannot read it through the same-origin policy. There are no plugin command permissions; built-in picker and opener plugins are called from authenticated Rust commands. The app command manifest opts commands into Tauri ACLs as another layer. Unit tests reject absent/forged tokens. Browser integration tests verify opaque-origin parent access rejection and script execution only after trust. Native WebKit validation is reported separately; browser tests alone are not evidence of native IPC isolation.

## Explicit trust

Enabling scripts allows raw HTML, document styles, event handlers, and JavaScript inside the frame. Scripts can inspect the entire rendered document and all preloaded image bytes, render arbitrary UI, consume CPU and memory, and attempt network activity. The document cannot edit the original file through Papyri. Trust is session-only and resets on source/tab changes or document revision changes. It is not a signature check. It does not validate a document's author or dependencies.

Trusted frames cannot request host navigation or update the saved document scroll state. The accepted messages from them are current-channel readiness, bounded zoom/width commands, diagram expansion state, next/previous selection among already-open tabs, and the acknowledgement of a control-initiated scroll. Safe previews may additionally send a selection-menu request carrying bounded selected text, its block-level Markdown source, sanitized preview HTML, and host coordinates, or a no-selection context-menu request carrying only coordinates; the host clamps the menu to the window and routes only local copy, quote, navigation, and Wikipedia actions. That acknowledgement reports only the resulting position for the control response; it is not stored as a scroll bookmark. Trusted frames accept no file paths and cannot read arbitrary files or open new documents; cycling selects cached tab content and revokes document trust. Diagram expansion keeps the same opaque-origin frame and its existing sandbox; no document HTML moves into the host DOM. Internal anchors scroll inside the frame. Every rendered frame also has a fresh random message channel; the host revokes the previous channel before asynchronous rendering starts. This rejects queued or repeated messages from the old frame while disabling trust or refreshing. This prevents document scripts from using the host as a privileged filesystem-navigation proxy. Direct same-origin parent access remains blocked by the opaque origin. The table of contents and search can still send commands into a trusted frame, but scripts may remove or replace the expected document DOM. Trusted frames do not update scroll bookmarks, so only safe previews guarantee scroll restoration.

**Network resource blocking is not a network sandbox for trusted JavaScript.** CSP blocks ordinary images, fetches, scripts and styles unless enabled, but a script can navigate its own frame to a network URL. Do not enable scripts if that behavior is unacceptable. The UI states this before granting trust. External links activated in safe documents open in the system browser with HTTP, HTTPS or mail schemes only; unknown schemes are rejected.

Opaque origins also prevent ordinary local-origin storage/cookies and make some CORS-dependent embedded apps incompatible. No promise is made that arbitrary web applications will work inside a document. Frames cannot contain further iframes in this release. Browser/WebKit security bugs, resource exhaustion and external applications launched for user-clicked links remain outside the application's complete control. Keep the platform WebKit and dependencies updated.

**The web browser panel is not a document frame.** It is a separate WebKitGTK view created outside Tauri's webview tree, with its own persistent `WebsiteDataManager`. It receives no host token, Tauri capability, or application command, so pages cannot use Papyri's filesystem API. User-entered navigation accepts only HTTP(S); `file:` and application schemes are blocked, while `mailto:` and `tel:` links go to the system opener. Visited sites receive and store cookies, local storage, and cache as in a normal browser, including sign-in credentials. Popups share the same data store. The panel is independent of the document network preference because it is an explicit browsing surface. Clearing the browser data directory signs out of all sites; do not put sensitive browser profiles on a shared account.

## PDF, Typst and LaTeX

LaTeX compilation uses the selected user-installed executable in an isolated Linux sandbox. Project files, the selected TeX Live installation when detected, and standard system runtime directories are read-only, network access and shell escape are disabled, and compiler output is temporary. The compiler can execute Lua code, and mounted files remain readable to it. See [document support](documents.md) for runtime paths and limitations.

PDFs, including compiled Typst output, are parsed by bundled PDF.js in the same opaque-origin preview boundary. PDF bytes are transferred after a current-channel handshake; document text never enters the privileged host DOM. There is no scripting manager, XFA support, form editing, attachment downloader, or document-launch handler. PDF resource fetches remain restricted to bundled data; enabling network resources additionally permits image and sandboxed-page requests for external link previews. Only user-activated links request validated host navigation. PDF.js and the OS webview must still be kept current; malformed files may consume resources despite page/canvas/input budgets.

Typst compilation runs the selected executable through Bubblewrap with separate user, process, mount, and network namespaces, dropped capabilities, cleared environment, read-only project/package mounts, and CPU/address-space/time/output limits. Sandbox failures never fall back to unsandboxed execution. The source folder is readable, so a Typst document can include any file within it in its PDF output; opening an untrusted document grants that scope. Standard system runtime directories and the Nix store are mounted read-only for the compiler. User home files outside the project and explicitly mounted Typst package caches are absent. Only a private temporary metadata directory is writable, and source files are never saved. See [document support](documents.md) for exact limits and package/font behavior.

## Privacy and dependency maintenance

No telemetry, analytics, document upload, crash reporting, account system or remote diagram service is included. Application preferences are stored locally. The optional browser panel stores site cookies, storage, and cache in an app-private directory so sign-in can persist. A hosted site necessarily fetches its own static assets, and documents with enabled external content may send requests to the referenced servers.

Run `npm audit`, review upstream advisories, and rebuild the Nix closure when upgrading. The initial dependency audit reports two low-severity development-tool findings through `deepmerge` in `@sveltejs/vite-plugin-svelte`, with no upstream fix offered. Production dependency findings are reported separately in verification. Do not expose the Vite development server to untrusted networks; its default binding is loopback.
