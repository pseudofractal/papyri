# Security model

Safe preview is the default. Markdown and raw HTML never enter the privileged application's DOM. DOMPurify sanitizes the rendered HTML inside an opaque-origin frame. The frame has `sandbox="allow-scripts"` solely so bundled renderers can run; it has no same-origin, forms, popups, downloads, top-navigation or nested-frame grants. A CSP restricts sources, blocks object embedding and form submission, disables network resources by default, and permits bundled Graphviz WASM without JavaScript `eval`. The host's CSP allows the bundled frame runtime and WASM. Tauri's automatic CSP modifications remain enabled. An inert meta tag uses the locked Tauri SDK's nonce placeholder, which Tauri replaces and authorizes per response. The host gives that nonce to the bundled frame runtime, which assigns it to document script elements only after explicit trust. No host-wide script/style policy relaxation is used; it is not the primary defense against document injection. The host never inserts document HTML into its live DOM.

The deferred diagram source is captured before document HTML enters the frame; document IDs cannot substitute executable content for that bundle. The parent scans static image references in an inert template, resolves them against the current document, checks type and byte budgets, and embeds bytes into the frame. This grants a document access to image files it references under the account's Linux permissions. Do not treat a document with arbitrary image paths as having no read access at all. User-selected web imports are confined to their selected file set; directory handles are confined to their grant. There is no message allowing a frame to request arbitrary bytes, and no global asset protocol granting a webview broad filesystem access.

Tauri warns that Linux cannot reliably distinguish iframe IPC from host requests. Therefore every application command additionally checks a random 256-bit per-process host token. Initialization exposes the token only when the frame is the top-level application at the expected application/dev origin. An opaque document cannot read it through the same-origin policy. There are no plugin command permissions; built-in picker and opener plugins are called from authenticated Rust commands. The app command manifest opts commands into Tauri ACLs as another layer. Unit tests reject absent/forged tokens. Browser integration tests verify opaque-origin parent access rejection and script execution only after trust. Native WebKit validation is reported separately; browser tests alone are not evidence of native IPC isolation.

## Explicit trust

Enabling scripts allows raw HTML, document styles, event handlers, and JavaScript inside the frame. Scripts can inspect the entire rendered document and all preloaded image bytes, render arbitrary UI, consume CPU and memory, and attempt network activity. The document cannot edit the original file through mdview. Trust is session-only and resets on source/tab changes or document revision changes. It is not a signature check. It does not validate a document's author or dependencies.

Trusted frames cannot request host navigation or report document scroll state. The accepted messages from them are current-channel readiness, bounded zoom/width commands, diagram expansion state, and next/previous selection among already-open tabs. They accept no file paths and cannot read arbitrary files or open new documents; cycling selects cached tab content and revokes document trust. Diagram expansion keeps the same opaque-origin frame and its existing sandbox; no document HTML moves into the host DOM. Internal anchors scroll inside the frame. Every rendered frame also has a fresh random message channel; the host revokes the previous channel before asynchronous rendering starts. This rejects queued or repeated messages from the old frame while disabling trust or refreshing. This prevents document scripts from using the host as a privileged filesystem-navigation proxy. Direct same-origin parent access remains blocked by the opaque origin. The table of contents and search can still send commands into a trusted frame, but scripts may remove or replace the expected document DOM. Trusted frames do not report scroll position, so only safe previews guarantee scroll restoration.

**Network resource blocking is not a network sandbox for trusted JavaScript.** CSP blocks ordinary images, fetches, scripts and styles unless enabled, but a script can navigate its own frame to a network URL. Do not enable scripts if that behavior is unacceptable. The UI states this before granting trust. External links activated in safe documents open in the system browser with HTTP, HTTPS or mail schemes only; unknown schemes are rejected.

Opaque origins also prevent ordinary local-origin storage/cookies and make some CORS-dependent embedded apps incompatible. No promise is made that arbitrary web applications will work inside a document. Frames cannot contain further iframes in this release. Browser/WebKit security bugs, resource exhaustion and external applications launched for user-clicked links remain outside the application's complete control. Keep the platform WebKit and dependencies updated.

## Privacy and dependency maintenance

No telemetry, analytics, document upload, crash reporting, account system or remote diagram service is included. Preferences alone are stored in local application/browser storage. A hosted site necessarily fetches its own static assets, and documents with enabled external content may send requests to the referenced servers.

Run `npm audit`, review upstream advisories, and rebuild the Nix closure when upgrading. The initial dependency audit reports two low-severity development-tool findings through `deepmerge` in `@sveltejs/vite-plugin-svelte`, with no upstream fix offered. Production dependency findings are reported separately in verification. Do not expose the Vite development server to untrusted networks; its default binding is loopback.
